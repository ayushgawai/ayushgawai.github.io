Zscaler · Jan 2024 – Jul 2025, and every build since

Systems that assume every input is hostile

A year and a half as a data engineer at a cloud-security company, where reporting accuracy drove decisions for product, security and GTM teams, and secure environments and least privilege were part of the job. The habit stuck: untrusted inputs get fenced, privileges stay minimal, and every decision leaves a trail.

The guardrails, as built

  • Untrusted, fenced. Report data is treated as untrusted content and the user's question as untrusted instructions. Both go inside a fenced context before they reach the model.
  • Bounded length. Question, report context and response are each capped, and large reports are cut down to the relevant rows plus compact history.
  • No execution tools. The model cannot rerun jobs, change configurations, run arbitrary queries or trigger any operational action.
  • Read-only data. Answers are grounded in the same published weekly snapshot the dashboard reads, so the output is text, not action.
  • Vault secrets. Bot and API credentials come from Vault under explicit least-privilege policies, never from config files.

The same habit, in public code

Each of these treats its inputs as hostile, keeps privileges narrow and leaves an audit trail.
