the layers under the application

Storage, query, performance and control planes

Below the application layer, the hard part is mechanism: how bytes survive a crash, how a query skips data it never needs, where a chip's roofline actually sits, and how a fleet of machines stays in sync. Here is how each of those works, drawn the way they behave.

Why these three

Each sketch is a different layer under the application: durable bytes on disk, the query planner, and a chip's performance roof. The mechanism is the point, not a throughput number.

Numbers, or not

LSMStore is deliberately unbenchmarked; the public repo says so. The query engine is verified by checking about 1,500 randomized queries against a row-at-a-time reference interpreter, and SiliconBench carries its measured GFLOP/s figures.

entries from the lab

  • lakelog Delta/Iceberg-style transaction log: optimistic commits via an atomic link, snapshots, and time travel.
  • pg-wal-lab Postgres C extension for WAL and MVCC inspection, with a crash-recovery harness built against Postgres 14–16.
  • orderbook-engine C++20 price-time priority matching: about 4.68M messages/s with a p99 of about 900 ns on a 2M-message replay.
  • edge-llm-roofline An analytical LLM-inference model for edge NPUs; its estimates match Jetson Orin and RTX 4090 measurements at 8.7% MAPE.
  • gpu attention lab On an RTX 5090, fused attention cut peak memory from 16,648 to 264 MiB at 16k tokens.
  • spec-decode-lab A draft model proposes tokens and a target model scores them in a batch, so the sequential passes drop while the output stays correct.
  • llm-shard-planner Plans dense and mixture-of-experts inference across devices, eliminating plans that exceed memory and ranking by prefill and decode.
  • gpu-job-orchestrator Go scheduler over 512 GPUs across AWS, GCP and on-prem, with gang scheduling and spot preemption rollback.
  • fleet-control-plane Go control plane with versioned desired versus reported config shadows, stale-version rejection, and heartbeat liveness.
  • dedup-store FastCDC content-defined chunking with SHA-256 fingerprints and a crash-resumable garbage collector.
  • sensor-hub-firmware Host-simulated hardware abstraction with 1 kHz sensor reads and a lock-free ring; no deployed MCU.

CarbonShift

GPU training that adapts its power limits, or pauses, to live grid carbon intensity and price, with GREEN, AMBER and RED states and checkpointing. FastAPI with live WebSocket updates. In simulation it cut carbon about 43% and cost about 37%.
