Zoox Perception · miner ops · 2026

An ops bot that can explain the fleet, never act on it

Slash commands return miner status, failing miners and precision; an LLM layer answers free-form questions from the same published weekly JSON snapshot the dashboard reads. The model gets no database access and no execution tools, report data and user text are fenced as untrusted, and question, context and reply are all length-bounded.

Technical deep dive

Architecture

  • Published weekly JSON snapshot → context selection → internal LLM API → read-only answer. The model cannot rerun miners, modify config, run arbitrary queries or trigger operations.
  • Prompt-injection defenses: report data treated as untrusted content, user questions treated as untrusted instructions, fenced report context, report-week grounding.
  • Bounded question, context and reply lengths. For large reports the context is reduced to the relevant miners and owners, with compact historical summaries kept for trend questions.

Ops tooling around it

  • Slash commands: status for all miners, one miner or one owner; failing miners; precision lookup; dashboard links; notification subscriptions; mute switches for noisy miners.
  • Ephemeral responses keep operational queries out of shared channels; failures reach owners as DMs.

Technical deep dive

Team

Team project with Manav Patel, WeMakeDevs submission, November 2026.

Flow

  • An upstream PR posts to a Switch schema-changes room; an impact coordinator on Claude Code broadcasts the impact-checker role to linked analytics, ML-feature and dashboard rooms.
  • Claude Code, Codex and OpenCode work in their own Git checkouts, run the upstream branch against local tests, and report the exact failing file and check.
  • Agents open Jira tickets and coordinated fix PRs; the coordinator writes a durable impact report and holds the upstream required check pending until every repo owner approves in Slack.

Properties

  • Parallel agents with bounded ownership, independent tests, a durable audit trail, least privilege, a failure impact graph and a human-controlled merge gate.
  • Demo: user_id → account_id broke six checks across analytics/dbt, ML features and dashboard SQL, producing three coordinated fix PRs and tickets. A non-owner's approval was rejected; the pipeline went green only after the legitimate owners approved. A harmless optional-column change reports no impact.
