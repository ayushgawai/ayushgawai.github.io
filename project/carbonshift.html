Devpost / TreeHacks · carbon-aware training

CarbonShift

GPU training that follows the grid: a 60-second control loop polls CAISO price and carbon, maps them to four Eco-Pulse states, and drives the A100's power cap through NVML — from full 250 W down to a checkpointed pause.

the numbers

43%lower carbon intensity in a realistic profile

37%lower energy cost, same throughput

4 statesGREEN / NORMAL / AMBER / RED → 250→100 W

2 sWebSocket state updates to the dashboard

how it works

  • Sensing: an async 60-second monitor polls CAISO OASIS (WattTime fallback) for $/MWh and gCO₂/kWh.
  • Decision: the Eco-Pulse engine maps thresholds over price and carbon to four states; GREEN raises the cap to 250 W, AMBER throttles to 150 W, RED saves a checkpoint, drops to 100 W and pauses.
  • Control: the GPU controller issues NVML power caps to the A100; the PyTorch training engine pause/resumes with a checkpoint manager, so a pause never loses progress.
  • Surface: FastAPI REST plus a WebSocket loop pushing state and running savings every 2 s to a React dashboard; a two-loop, two-clock design keeps the control loop (60 s) separate from the UI loop (2 s).

the design calls

Throttle before pausing

Power caps keep training moving; only RED stops it.

Checkpoint on every pause

A red pause is free to resume — no progress lost.
