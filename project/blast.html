Blast Radius: one rename, three repos, six failures caught before merge

An upstream schema PR triggers an impact coordinator that broadcasts an impact-checker role to linked analytics, ML-feature and dashboard rooms. Three coding agents across providers run the upstream branch against local tests in their own Git checkouts, report the exact failing file and check, and open Jira tickets and fix PRs. A required check stays pending until every repo owner approves in Slack.

  • 6 downstream checks caught
  • 3 fix PRs, 3 agents
  • 1 owner-only merge gate

Technical deep dive

Team

Team project with Manav Patel, WeMakeDevs submission, November 2026.

Flow

  • An upstream PR posts to a Switch schema-changes room; an impact coordinator on Claude Code broadcasts the impact-checker role to linked analytics, ML-feature and dashboard rooms.
  • Claude Code, Codex and OpenCode work in their own Git checkouts, run the upstream branch against local tests, and report the exact failing file and check.
  • Agents open Jira tickets and coordinated fix PRs; the coordinator writes a durable impact report and holds the upstream required check pending until every repo owner approves in Slack.

Properties

  • Parallel agents with bounded ownership, independent tests, a durable audit trail, least privilege, a failure impact graph and a human-controlled merge gate.
  • Demo: user_id → account_id broke six checks across analytics/dbt, ML features and dashboard SQL, producing three coordinated fix PRs and tickets. A non-owner's approval was rejected; the pipeline went green only after the legitimate owners approved. A harmless optional-column change reports no impact.

the design calls

Parallel agents, bounded ownership

Each provider works in its own checkout; ownership and test scope are explicit.

Human-controlled merge gate

The impact report stays pending until the humans approve, least privilege by construction.
