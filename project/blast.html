Blast Radius

Answers the data-engineer's scariest question — 'if I rename this upstream field, what breaks before I merge?' — with a fleet of coding agents and a human-controlled merge gate.

the numbers

6downstream checks broken by one user_id → account_id rename

3 providersClaude Code, Codex and OpenCode working in own checkouts

3coordinated fix PRs + tickets, all owner-approved

1harmless optional-column case correctly reported as no-impact

how it works

  • Trigger: an upstream PR posts to a Switch schema-changes room; an impact coordinator on Claude Code broadcasts an impact-checker role to linked analytics, ML-feature and dashboard rooms.
  • Bounded ownership: three agents work in their own Git checkouts, run the upstream branch against local tests, and report the exact failing file and check.
  • Repair: agents open Jira tickets and fix PRs, then wait for owner authorization — a non-owner's approval is rejected in the demo.
  • Gate: the coordinator writes a durable impact report and holds the upstream required check pending until every repo owner approves in Slack; the demo ends green only after legitimate owners sign off.

the design calls

Parallel agents, bounded ownership

Each provider works in its own checkout; ownership and test scope are explicit.

Human-controlled merge gate

The impact report stays pending until the humans approve — least privilege by construction.
