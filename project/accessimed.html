Accessibility engineering tooling

AccessiMed

A CLI-first accessibility scanner with reviewable fixes: Playwright + axe-core audits against WCAG 2.1 A/AA, deterministic or LLM remediation, and every change ships as a reviewed git diff into a CI gate.

the numbers

WCAG 2.1A/AA levels via axe-core in a real browser

2fix strategies: deterministic no-key fallback + LLM

SQLitescan and remediation history, plus PDF reports

CIGitHub Actions gates keep it green

how it works

  • Scan: install the CLI, initialize .accessimed.toml, then audit local HTML or run a real browser with Playwright and axe-core against WCAG 2.1 A/AA; findings normalize to severity and rule IDs (alt text, labels, button/link names, page language).
  • Fix: pick a finding and get a deterministic exact-match patch where one exists, or an LLM suggestion where it doesn't, detection is separated from remediation.
  • Review: apply the fix to source, review the git diff, re-run the checks; SQLite stores scans and remediation history and powers PDF reports and an optional FastAPI + React/Vite dashboard.
  • CI: GitHub Actions and automated test gates make accessibility a merge gate, not a one-time audit.

the design calls

Deterministic first, LLM second

No-key fallbacks are fully predictable; the LLM only covers what rules can't.

Nothing applies silently

Every change is a reviewed diff, a human is always in the loop.
