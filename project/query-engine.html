LSMStore · Java 17

An LSM-tree key-value store

Fsynced write-ahead log, sorted TreeMap memtable, and immutable SSTables published by temp-file + atomic rename. Reads go newest to oldest, and per-table Bloom filters (10 bits/key, 7 hashes) answer most misses without a disk read.

  • fsyncbefore the memtable
  • 10 b/keyBloom, 7 hashes
  • WAL replayon restart

Technical deep dive

Write path

Append-and-fsync to the WAL, then insert into a sorted TreeMap memtable. A full memtable flushes to an immutable sorted SSTable written to a temporary file and published by atomic rename, so readers only ever see whole tables.

Read path

Memtable first, then SSTables newest to oldest using in-memory key-offset indexes. Each table's Bloom filter is checked before its index, so a negative verdict costs no I/O. Deletes are tombstones that shadow older values.

Compaction and recovery

A four-SSTable trigger merges tables in memory into one compacted table (a simple merge trigger, not leveled compaction). Startup replays the WAL and drops only a truncated final record.

The public README says not benchmarked yet, so no throughput numbers are claimed here.

query-engine · C++20

A vectorized columnar query engine

Logical plans are rewritten by constant folding, filter pushdown through projections and joins, and column pruning, then executed in 2,048-row batches over column and selection vectors. Per-column min/max stats in each row group let the scan skip groups before deserializing them.

  • 2,048rows per batch
  • ~1,500random queries vs a reference
  • ~4MTPC-H-like line items

Technical deep dive

Plan and optimizer

  • Explicit logical plan: Scan, Filter, Project, Aggregate, HashJoin, Limit.
  • Passes: constant folding, filter pushdown through projections and joins into scans, unused-column pruning. Pushdown has to stay correct across outer joins and aggregates.

Executor and file format

  • Batch-at-a-time vectorized execution over column vectors with selection vectors, 2,048 rows per batch.
  • Row-group columnar files with dictionary encoding, footer metadata and per-column min/max stats for data skipping.

Verification

About 1,500 randomized queries checked against a row-at-a-time reference interpreter on TPC-H-like data (about 4M line items, 1M orders).

Technical deep dive

The SGEMM climb

Reordering the loop nest lifted SGEMM from 1.27 to 13.17 GFLOP/s (10.4×) by making the inner loop walk memory contiguously. Cache blocking plus OpenMP then reached 36.11 GFLOP/s: tiles are reused from cache and spread across cores, moving the kernel toward the compute roof.

Method

Every variant is checked for correctness first, including odd lengths and non-square shapes. Warmups, repeated runs and median reporting keep numbers stable; perf counters and arithmetic-intensity reasoning place each kernel on the roofline. Targets AWS Graviton and Inferentia2 with the AWS Neuron SDK and NKI.
