CarbonShift

A 60-second control loop polls CAISO grid price and carbon, maps them to GREEN, NORMAL, AMBER or RED, and sets the A100 power cap through NVML, from 250 W down to a checkpointed pause. In a realistic scenario profile it cut carbon intensity ~43% and energy cost ~37%.

Columnar query engine

A rule optimizer folds constants, pushes filters through projections and joins into scans, and prunes columns. Footer min/max stats then skip 63 of 80 row groups on a one-year filter, and 2,048-row batches with selection vectors run the rest. 1,500 random queries match a row-at-a-time oracle.

WikiRisk

Spark ingests 29+ GB of Wikipedia revision history and cross-validates a SparkML model on 11.16M rows in MLflow, then a live Structured Streaming job scores every Wikimedia edit as it lands. Scored events go to a Parquet archive and a SQLite + FastAPI serving layer. Held-out recall is 89.6% at 0.762 ROC AUC.

Ready Builders Challenge · March 2026

LEO satellite coverage risk

Scores tree and terrain obstruction risk for LEO broadband at every candidate site in North Carolina by sampling NLCD canopy and land-cover rasters and USGS 3DEP elevation and slope. A Claude tool-use orchestrator sequences five deterministic Python tools over file-based state, so row data never enters the prompt.

  • 4.67M sites scored
  • 100/100 counties covered
  • 5 deterministic tools
  • 250 tests
Code on GitHub Open on Loom
Technical deep dive

Data chain

Location IDs and coordinates join NLCD and USGS canopy rasters, USGS 3DEP elevation with derived slope, and NLCD land-cover classes. Each site is spatially sampled, component-scored into HIGH, MODERATE or LOW tiers against Starlink installation guidance, and validated for coordinates and coverage before a scored CSV, charts and reports are written.

Agent architecture

  • Claude tool use picks the next step across ingest_locations, sample_environment, score_risk, validate_results and generate_report.
  • Python does all geospatial and numeric work; state passes as artifact paths, never as rows.
  • A pipeline-only mode runs the same functions with no LLM, so results are reproducible.
  • Interactive tools answer coordinate, address, area, polygon and nearby-alternative queries over precomputed scores, behind a map and search UI.

March 2026 run

4,674,905 of 4,674,905 sites scored; 100 of 100 counties; 0.0% missing environmental values; tiers HIGH 19.4%, MODERATE 31.3%, LOW 49.3%.

HP × SJSU Edge AI Hackathon · winner

Sentinel AI

YOLO26s-pose tracking and per-track temporal rules on an HP ZGX Nano gate a 16-frame evidence bundle into a local Qwen3-VL-30B-A3B FP8 classifier. Owned the frame-streaming backend, async event routing, alert triggers and incident log.

  • 13–14 fps, six-feed wall
  • 16 frames per VLM call
  • 6 incident classes
Code on GitHub
Technical deep dive

Escalation funnel

Frame decode feeds a person detector and tracker; per-track rules (weapon, fall, run, loitering, sudden change) score events, and only credible ones open a 16-frame window for Qwen3-VL served through HP Z Runtime, which returns WEAPON, FIGHT, THEFT, RUN, MEDICAL or BENIGN plus a person description. Cheap per-frame perception carries the volume; VLM reasoning is spent only on ambiguous, high-impact events.

Backend

Severity thresholds drive an incident state machine (NEW, ALERTED, DISPATCH_PENDING, DISPATCHED, TRACKING, RESOLVED or DISMISSED) with SQLite history and REST, WebSocket and MJPEG console updates. A voice-dispatch path needs human confirmation, has a kill switch, one call per incident and a fixed camera-to-address map.

Ownership and caveats

Team project; owned the video and frame-streaming backend, async event routing, alert triggers and incident logging. Wall throughput rose from about 3 fps to 13–14 fps with three full-analysis feeds; 640 of 649 frames matched the demo clip's labels (not a formal benchmark). Demo calls never reached real 911.

Technical deep dive

Flow

An upstream PR posts to a schema-changes room; the impact coordinator (Claude Code) broadcasts an impact-checker role to linked analytics, ML-feature and dashboard rooms. Claude Code, Codex and OpenCode agents run the upstream branch against local tests in independent checkouts, open Jira tickets and fix PRs, then wait for owner authorization while the coordinator writes a durable impact report.

Demo run

Renaming user_id to account_id broke six checks across dbt models, ML features and dashboard SQL, produced three coordinated fix PRs, and rejected a non-owner's approval; the gate turned green only after the real owners approved. A harmless optional-column rename reports no impact.

Design

Two-person team project. Bounded agent ownership, independent tests, least privilege, an audit trail and a human-controlled merge gate.

Grid-aware training control

CarbonShift

WattTime and CAISO signals polled every ~60 s drive a GREEN, AMBER, RED, NORMAL state machine that sets A100 power limits, with checkpointed pause and resume. FastAPI exposes control endpoints and streams telemetry over WebSocket every ~2 s.

  • ~43% less carbon, simulated
  • ~37% lower cost, simulated
  • ~60 s control period
Code on GitHub Devpost
Technical deep dive

Control loop

A grid monitor (WattTime and CAISO, with a mock fallback) feeds the Eco-Pulse arbitration engine; its state sets a GPU power-limit target, and a checkpoint manager pauses and resumes training when the grid is dirtiest. A background metrics loop backs the FastAPI status endpoints, WebSocket updates and cumulative cost and carbon accounting.

Trade-offs

Power capping instead of pure scheduling keeps jobs progressing; the poll period and state hysteresis avoid thrashing between limits.

Caveat

The ~43% carbon and ~37% cost reductions are simulated scenario results, not measured datacenter savings. A LangGraph supervisor, planner and executor layer is a later extension; the public repo documents the mock-enabled control loop.

SJSU robotics lab · LeRobot

SO-101 arm, imitation learning

ACT policy with a ResNet-18 backbone, trained from scratch on 50 teleoperated SO-101 demonstrations and compared against a SmolVLA fine-tune. Traced reverting servo IDs to a Feetech EEPROM lock that was never re-set, which unblocked calibration.

  • 46/50 picks, fixed cube position
  • ~18 ms ACT vs ~251 ms SmolVLA
  • 50 demos, ~110k frames
Code on GitHub
Technical deep dive

Setup and data flow

Six-joint SO-101 leader and follower arms on Feetech STS3215 servos over USB motor buses, with a gripper and paired RGB cameras, calibrated and teleoperated through Hugging Face LeRobot. 50 demonstrations (about 49,633 and 59,998 frames in two datasets) passed integrity validation, then trained ACT from scratch (30k- and 60k-step runs) and fine-tuned SmolVLA (20k steps) before physical rollouts.

Results and caveat

ACT completed 46 of 50 pick-and-place trials at a fixed cube position (demo positions varied under 1 cm), 2.49 cm mean placement error on successes. That does not establish generalized success; randomized-position evaluation is unfinished.

Ownership

Two-person research build. Owned calibration, teleoperated data collection, resumable 50-trial rollout scripts, video-measured placement error, a failure taxonomy, camera-dropout handling and checkpoint-selection analysis.

The EEPROM bug

Follower IDs reverted after power cycles and the wrist-roll and gripper collided on one ID. The EEPROM was unlocked for an ID write and never re-locked; patching LeRobot's motor-bus setup to write Lock=1 after ID or baud changes made IDs persist.

Findings and scope

Fixation count was the strongest discriminator among the measured oculometrics. In the wheelchair study, seatback vibration plus instructional cues produced faster obstacle responses; it measures response timing, usefulness and preference, not real-world crash reduction. The published apparatus is the onboard GPU laptop with the ZED 2i; a Jetson and LiDAR C++ prototype is a separate project.
