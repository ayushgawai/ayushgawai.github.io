what I did

  • The migration: ~800 TB of enterprise data moved from HDFS to AWS S3, with AWS Data Sync handling the transfer and bash scripts tracking and validating every copied batch.
  • Controlled, not fire-and-forget: a Delta Lake–style validation framework with Python and pytest-style dataset checks diffed source and destination for row mismatches, null anomalies and type drift, 99.6% validation accuracy before go-live, which is what kept it from becoming a client escalation.
  • SLAs: CloudWatch metrics, SNS alerting and reactive Lambda triggers orchestrated in Airflow; root-cause traces cut time-to-detection of pipeline failures, reducing client escalations by ~45%.
  • Performance: layered CTE rewrites, partitioning and execution optimization took a major reporting pipeline from ~18 minutes to 6; containerized operators and modular DAGs moved legacy Airflow pipelines to managed (MWAA-style) environments.

Technical deep dive

Risks at this scale

Corruption in transit, schema drift, partial ingestion, silent batch-job errors and SLA breaches on client reporting.

Validation framework

  • Delta Lake patterns to track changes; Python validation logic with pytest-style dataset tests.
  • Programmatic source-vs-destination comparison: row mismatches, null anomalies, type inconsistencies, all flagged before release.

Monitoring and SLAs

CloudWatch metrics, SNS alerting and Lambda triggers on top of Airflow detect SLA breaches and job failures and log root-cause traces; client escalations fell about 45%.

Orchestration

Legacy Airflow upgraded to managed MWAA-style patterns: containerized operators, modular DAGs, isolated per-workflow tests, better retries, fewer failed deploys.

Performance

Layered CTEs restructured, partitioning re-planned for pruning instead of wide scans, resources and query plans tuned: one major reporting model went from about 18 to 6 minutes. Stack: Python, Spark/Databricks, Snowflake, S3, Lambda, CloudWatch, Airflow.
