what I did

  • The fix was a compiler, not a prompt: pulled formula definitions via the ObjectDetails API, extracted complete formula logic, ran a depth-first traversal over nested field dependencies, and emitted structured JSON context (dependency graph + formula text) into an LLM that produced optimized SQL, inserted into version-controlled dbt models.

  • Redesigned ingestion around incremental upserts and change detection, with partitioning and clustering tuned for Snowflake on location-based attributes; heavy transforms stayed in the warehouse, off the request path.

Zscaler · Data Engineer · 2024–2025

Compiling Salesforce formulas into incremental SQL

Formula fields recompute without bumping LastModified, so incremental loads missed changes and fell back to full refreshes. A metadata compiler walks each formula’s dependency graph depth-first, has an LLM emit SQL from that structured context, and lands it in versioned dbt models fed by Matillion upserts. Sampled rows are reconciled against live CRM before deploy.

  • ~80% lower reporting latency
  • ~35% faster queries
  • DFS → SQL formula dependency compiler
Technical deep dive

Problem

Leadership dashboards and adoption metrics depended on Salesforce formula fields that recalculate in real time but never update LastModifiedTimestamp. Incremental logic broke, full-table refreshes raised latency and warehouse cost, and nested, undocumented field dependencies left no way to trace impact.

Metadata compiler

  • Pull formula definitions through the Salesforce ObjectDetails API.
  • Depth-first traversal maps every upstream field dependency; each formula gets a structured JSON context.
  • Dependency graph plus formula logic go to an LLM, which generates SQL; output lands in dbt models, so the logic becomes deterministic, versioned and reviewable.

Ingestion

  • Change detection and incremental upserts replace full-table refreshes; modular transformation layers.
  • Partitioning and Snowflake clustering on location attributes cut scan volume for spatial-style queries.

Verification

  • LLM-generated SQL is a risk, so automated sampling compares warehouse output with the live CRM and flags discrepancies programmatically; reconciliation dashboards track it.
  • Git workflows with automated schema checks and SQL tests in GitHub Actions; Docker for identical environments.

Also

API integrations for LinkedIn Campaign, Asana and Jira, schema-normalized into the warehouse for marketing and delivery dashboards. Stack: Python, SQL, Snowflake, dbt, Matillion, AWS (S3, EC2), Docker, GitHub Actions.
